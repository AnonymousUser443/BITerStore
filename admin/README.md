# BITerStore 后台管理使用手册

后台地址：`https://store.young581.com/admin/`

后台用于查看运营数据、管理用户、治理商品、处理举报和追溯审计日志。所有写操作都要求填写处置原因，并记录操作人、对象、原因与请求标识。

## 1. 角色与权限

| 角色 | 能力 |
| --- | --- |
| `MODERATOR` 协管员 | 管理普通用户、商品和举报工单 |
| `ADMIN` 管理员 | 管理普通用户和协管员、商品及举报工单 |
| `SUPER_ADMIN` 超级管理员 | 包含全部治理能力，并可授予或移除协管员/管理员角色 |

管理员不能处置自己，也不能处置同级或更高权限账号。后台不提供授予 `SUPER_ADMIN` 的按钮；首次超级管理员或特殊恢复只能在服务器中完成。

## 2. 首次启用

### 2.1 准备账号

目标用户必须先在正式站点完成校园身份登录，账号状态必须为“正常”，校园认证状态必须为“已认证”。

### 2.2 在服务器授权

进入生产目录后，使用学号或用户 ID 二选一。不要把真实学号写入仓库、脚本或聊天记录。

```bash
cd /home/young/biterstore

# 首位超级管理员
docker compose -f deploy/config.yaml exec \
  -e STUDENT_NUMBER='<学号>' \
  -e ADMIN_ROLE='SUPER_ADMIN' \
  api npm run admin:promote
```

也可以使用 `USER_ID='<用户ID>'` 替代 `STUDENT_NUMBER`。可选角色为 `MODERATOR`、`ADMIN`、`SUPER_ADMIN`。

已有超级管理员可直接在“用户管理 → 处置”中把普通用户设为协管员或管理员，无需再次进入服务器。

### 2.3 设置动态验证码

1. 使用刚授权的账号登录正式 H5。
2. 打开 `https://store.young581.com/admin/`。
3. 点击“使用当前网站登录状态”。
4. 首次进入时点击“生成动态验证码密钥”。
5. 在 Microsoft Authenticator、Google Authenticator 等验证器中打开配置链接，或手动输入页面显示的密钥。
6. 输入验证器显示的 6 位验证码并启用。
7. 再输入一组当前验证码进入后台。

密钥启用后不会再次显示。动态验证码验证成功后签发短期后台会话，过期后需要再次输入验证码。

## 3. 日常使用

### 数据看板

查看注册用户、有效商品、在售商品、成交标记、近 7 日新增和待办举报。数字是打开或刷新页面时的数据库实时统计。

### 用户管理

- 可按昵称、学号、账号状态、校园认证状态和角色筛选。
- 点击“处置”直接打开页面确认框，在其中选择账号状态、安全或角色操作，再填写原因确认，不会展开表格内下拉菜单。
- 可恢复、禁言或封禁账号，也可强制下线该用户的全部设备。
- 封禁账号会同时撤销现有登录会话。
- 超级管理员可授予 `MODERATOR` / `ADMIN`，或移除后台角色。

### 商品治理

- 可按书名、作者、ISBN、卖家和商品状态筛选。
- 商品名称下方的“查看详情”会在新标签页打开正式 H5 商品详情，便于核对图片、描述、卖家和交易状态。
- 点击“处置”会直接在页面上打开确认框；选择“忽略”会记录处置结果并从默认待处置列表移除，确认违规时填写原因并选择“违规屏蔽”。
- 可通过“处置状态”筛选查看待处置、已处置或全部商品；已忽略商品仍保留原销售状态。
- 每次状态变更都会增加商品版本号，避免客户端用旧版本覆盖治理结果。

### 举报工单

- 待处理工单可以先标记为“处理中”，再选择结案或驳回。
- 处置原因会成为工单结论，并记录当前处理人。
- 页面会尽量解析被举报的商品或用户；对象已删除时仍保留原始对象 ID。

### 审计日志

审计日志支持按动作、资源、对象 ID 或操作人搜索。这里用于复核谁在何时对什么对象执行了什么操作以及原因。

## 4. 动态验证码丢失

该操作会清除管理员的 TOTP 密钥并撤销其全部登录会话，必须在服务器中明确确认：

```bash
cd /home/young/biterstore
docker compose -f deploy/config.yaml exec \
  -e STUDENT_NUMBER='<学号>' \
  -e CONFIRM_TOTP_RESET='RESET' \
  api npm run admin:reset-totp
```

完成后让该管理员重新登录 H5，再访问 `/admin/` 设置新的动态验证码。不要通过聊天、截图或工单传输 TOTP 密钥。

## 5. 常见问题

- **提示“需要登录”**：先回到正式 H5 完成校园登录，再打开后台。
- **提示“需要已认证且状态正常的管理员账号”**：检查账号是否已校园认证、是否被封禁，以及数据库中的后台角色。
- **看不到角色授权操作**：只有 `SUPER_ADMIN` 可以授予或移除后台角色，且不能操作同级超级管理员。
- **后台会话失效**：重新输入 6 位动态验证码即可；不要长期保存或分享 access token。
- **处理按钮不可用**：已结案工单、当前管理员本人、同级/更高角色或不适用的商品状态会被主动限制。

```powershell
cd F:\BITerstore\app\admin
npm test
npm run build

cd ..\server
npm run lint
npm test
npm run build
```
