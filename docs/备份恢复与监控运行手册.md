# 梨苑儿备份恢复与监控运行手册

更新时间：2026-09-15

## 备份边界

- PostgreSQL：`backup` 容器每天生成带完整性保护的 `biterstore-<UTC时间>.dump.gpg`，本地保留 7 天。
- 本机上传：使用 `UPLOAD_STORAGE=local` 时，`api-uploads` 卷必须与数据库归档处于同一备份批次。
- R2：使用对象存储时，应启用对象版本/保留策略，并将数据库归档同步到另一个私有位置。
- 加密口令只放在宿主机 `deploy/secrets/backup-passphrase.txt`，不得提交、写入镜像或与归档存放在同一位置。`.env` 的 `BACKUP_RUN_UID`、`BACKUP_RUN_GID` 必须与口令文件及 `deploy/backups` 目录所有者的数字 UID/GID 一致；保持口令文件为 `0600`，不要通过放宽权限解决容器读取问题。

## 每日检查

1. 确认过去 26 小时内产生了新的 `.dump.gpg`，文件大小不为 0，`backup` 容器没有持续重启。
2. 确认异地同步成功，远端文件大小与本地一致。
3. 请求 `/api/v1/health/ready`，四项检查均应为 `ok`；计划维护时才允许明确记录的 `skipped`。
4. 检查公开列表/搜索/详情的请求量、`429` 比例、缓存命中率、数据库活动连接和慢查询。

## 隔离恢复演练

至少每月执行一次，且只能恢复到新建的空白演练数据库。脚本会拒绝 `biterstore`、`postgres` 和模板库名称。

```bash
docker compose -f config.yaml exec \
  -e RESTORE_DATABASE_URL='postgresql://<user>:<password>@<isolated-host>:5432/biterstore_restore_drill_YYYYMM' \
  backup restore-drill.sh /backups/<archive>.dump.gpg
```

恢复完成后人工抽查迁移记录、用户数、商品数、会话数和图片引用；再用只读账号执行应用 smoke test。记录归档时间、恢复开始/结束时间、抽查结果和执行人。演练数据库由运维人员在确认记录完成后单独销毁，脚本不会自动删除数据库。

## 初始告警线

- readiness 连续 3 次失败，或 5 分钟错误率超过 2%。
- PostgreSQL 活动连接持续超过池上限的 80%，查询 P95 超过 300ms，或出现超过 1 秒的公开列表慢查询。
- 公开接口 `429` 比例连续 5 分钟超过 10%，单 IP/参数基数突增，或全站公开读取达到配置总限额的 80%。
- Redis 内存超过 75%、出现淘汰突增或认证失败；R2 请求错误率超过 1%。
- 26 小时无新备份、备份完整性失败、异地同步失败，或月度恢复演练逾期。

告警阈值应在隔离压测与一周真实基线后调整。Cloudflare 速率/Bot 规则、异地存储、告警接收渠道和真实恢复演练属于外部运维配置，代码不会自动代替这些操作。
