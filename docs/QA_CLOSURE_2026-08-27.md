微信自动化覆盖以下流程：

1. 欢迎页 → 三步引导 → 游客访问 → 首页。
2. 搜索 → 商品详情 → 收藏 → 联系卖家。
3. 图片 fixture → Tobby 成文 → 草稿 → 预览 → 发布成功。
4. 消息 → 通知详情 → 聊天 → 文字与图片消息。
5. 收藏 → 我的 → 重置演示数据 → 重播引导。
6. Loading、Searching、Empty、No Results、Network Error、Maintenance、Unavailable、Success 与 404 状态。

## 本轮修复与守门

- 统一双端底栏为“首页 / 搜索 / 发布 / 消息 / 我的”。
- H5 视觉脚本自行启动静态 SPA 服务，避免依赖人工启动预览进程。
- H5 浏览器 profile 与双端 QA 工件位于微信项目监听目录之外，避免截图/缓存写入触发连续重编译和 `appLaunch timeout`。
- H5 图片适配层对首屏图片使用 eager/high，其余图片默认 lazy，并统一异步解码。
- 新增版本化 H5 性能检查，预算超限会直接令 QA 失败。
- 微信 E2E 保留原始 DevTools 日志，只精确标记已知的失效 WebView `routeDone` 工具噪声；任何应用错误或异常仍会阻断通过。
- 微信独立 `launch` 验收发现旧通道时使用 CLI `quit → auto` 刷新并等待模拟器，再由官方 `miniprogram-automator.connect` 驱动页面并在结束时安全关闭；`connect` 只复用人工 watch 会话。

## 仍需人工完成

至少使用一台实体微信真机完成以下冒烟，之后才可勾选 `TODO.md` Phase 7：

- 首次打开显示“托比正在准备 App 资源包……”，再次打开不重复等待。
- 五个底栏入口、页面返回栈和 Safe Area 正常。
- 搜索、筛选、详情、收藏、联系卖家流程可用。
- 发布页实际选择相册图片，输入法顶起时表单和按钮不被遮挡。
- 聊天输入、图片入口、长列表滚动和页面恢复正常。
- 360–430 px 等效手机宽度下无横向溢出、错位或不可点击区域。

真机冒烟只做本地预览/调试，不上传体验版，不提审，不发布。

## 已知环境风险

仓库锁定 Node 22.13.x；本轮执行机器为 Node 25.2.1。当前构建及自动化均通过，但最终真机验收和团队持续开发应使用锁定版本。Taro 4.2.1 的上游传递依赖告警仍按 `TODO.md` 记录处理，不使用 `npm audit fix --force` 破坏精确版本约束。
