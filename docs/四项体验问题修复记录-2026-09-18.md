# 四项体验问题修复记录

日期：2026-09-18（UTC+8）。对应用户反馈：审核期间无法看详情、返回偶发刷新、侧边滚动条、举报进度缺少对象和结果。

## 实际修改

| 问题 | 原因与修复 |
| --- | --- |
| 审核期间详情不可见 | 后台“查看详情”错误跳到公开商品页，公开接口会隐藏待审核商品。新增受 `AuthGuard`／`AdminGuard` 保护的后台详情接口和详情弹窗；商品治理、举报工单均从后台查看完整描述、价格、状态、卖家及审核图片／ISBN 凭证。没有放开待审核商品的公开访问。前台卖家原有 owner 详情接口另经回归确认可用。 |
| 返回偶发刷新感 | Golden Reference 与 Taro 同时消费 `popstate`，Taro 异步重挂页面，导致页面已显示后再次切换。H5 入口在 Taro 之前分发由本应用创建的历史项；应用只处理一次返回，并手动恢复滚动位置。浏览器回归持续检查同一应用 DOM、滚动位置和卡片动画，修复前可复现重挂载，修复后连续 10 次通过。 |
| 侧面滚动条 | 原有规则只覆盖部分滚动容器，弹窗等容器仍可能显示滚动条；视觉工具还使用浏览器强制隐藏滚动条参数，掩盖了问题。H5／后台统一隐藏轨道但保留滚动；微信聊天显式关闭原生滚动条。巡检移除强制隐藏参数，实际检查页面 CSS。 |
| 举报进度过少 | 旧通知只有处理人填写的说明。新增仅允许举报人查看的 `/reports/mine` 游标分页接口，双端系统通知页显示举报对象、完整编号、原因、状态、处理说明及提交／更新时间。历史工单也从现有 Report 数据读取，缺失说明明确标注，不编造结论。新通知同时记录对象、编号、原因及状态／结果，不再截断到 300 字。 |

通知分类页标题统一使用“系统通知”等分类名，避免把最新一条通知标题当作整个页面标题。
